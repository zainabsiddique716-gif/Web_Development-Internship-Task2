
# Contributing Guidelines

## Merge Strategy

We use **Squash and Merge** for all pull requests into `main`.

- Keeps commit history clean and linear
- Multiple small commits in a PR get combined into one commit
- The PR title becomes the squashed commit message — write it clearly and descriptively

## Pull Requests

- Create a feature branch off `main` for any change
- Open a PR before merging — direct pushes to `main` are not allowed
- At least 1 approval is required before merging

## Review Comment Labels

When reviewing PRs, prefix comments with one of the following:

- `blocker:` — must be fixed before merge
- `issue:` — a problem, but not blocking
- `nit:` — minor/optional suggestion
- `praise:` — highlighting good work
